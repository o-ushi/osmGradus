## ① ユーザーの狙いに反して重複している機能

| 判定 | 内容 |
|------|------|
| **意図的残置** | 「訳を付ける」（`LongArticleVocabEnrichScreen`）は本文タップで登録した語（`_registeredWordIds`）だけを対象にする。生成時の9語（`vocabTestWords`）は完全に別の状態（`LongArticle.vocabTestWords`）で、`entryIds`にも渡らない。9語の再翻訳を促すUIは無い。 |
| **意図的残置** | 標準「語彙テスト」（`Layer1VocabScreen`のプール抽選10問）と長文の9問は`fixedEntries`の有無で出題ソースが完全に分離。`fixedEntries != null`のときはレベル選択・プール抽選UIを出さない（既存ガードのまま）。 |
| **意図的残置** | 1秒チェック（`LongArticleComprehensionCheckScreen`、文脈理解の2択）と語彙テスト（`Layer1VocabScreen`、単語の音声/キーボード再生）はAIプロンプト上も役割を明記して分離（「1秒チェックとは別役割」）。同趣旨の設問にはならない。 |

致命的な「同じことを別実装でやっている」二系統は無い。

## ⑤ ＋長押し／ダブルタップの抜け漏れ

| 判定 | 内容 |
|------|------|
| **修正済（Step 8）** | 読解操作バー（`LongArticleActionRow`）: 「訳を付ける」（既存）・「単語帳」（新規、長押しで使い方シート）・「次へ」（ヒント文言を新規キーへ差し替え、チェック／語彙が続くことが分かる文言に）。 |
| **確認（意図的に対象外）** | 1秒チェックの選択肢A/B・完了ボタンはフルテキストの`InkWell`/`FilledButton`で、長押しの副次アクションを持たない。ダブルタップヒント（`ButtonActionHint`）は既存アプリ全体でも「アイコンのみ・長押しに副アクションがあるボタン」にのみ付与されており、同種の他画面（例: レイヤーⅡ〜Ⅴの2択/4択カード）にも同様のヒントは無い。抜けではなく既存方針の一貫適用。 |
| **確認（変更不要）** | 語彙テスト画面（`Layer1VocabScreen`）は長文経路でもUIを変更していないため、既存のヒント配線（45/60/15+60・＋）がそのまま引き継がれる。中央のサイコロ／マイクボタン（`PronunciationMicButton`）はコード内コメントで明記済みの「ダブルタップの機能ヒントには対応しない」という既存設計であり、長文経路固有の抜けではない。 |
| **確認** | 問題文解析側（`Layer1QuestionPromptDetailScreen`の「＋」長押し）・標準語彙テスト側の既存ヒントは、フルテスト（`flutter test`）で回帰なしを確認済み。今回の変更（`Layer1VocabScreen`への`gradedLongArticle`/`onLongArticleGraded`追加、`_pasteAndSaveResult`の分岐追加）は`widget.gradedLongArticle`のnullチェックで完全に分離しており、問題文経路のコードパスは変更していない。 |

## 手動確認の目安

1. 長文読解を新規生成（9語＋1秒チェック付き）→ 1秒チェックに正解／不正解どちらで答えても、ボタンが「語彙テストへ進む」と表示され、押すと語彙テスト画面が開く（3択には戻らない）
2. 語彙なしの旧データ・1秒チェックのみの旧AIレスポンスでは、ボタンは従来どおり「トップへ戻る」のまま
3. 語彙テストの採点完了（結果ダイアログの「完了」）で、スワイプ不要に自動的に3択画面へ戻り、「長文を保存しました」SnackBarは1回しか出ない
4. 長文一覧で正解率をタップ→詳細（`VocabularyCheckDetailScreen`）が開き「長文の見直し」バッジが付く。IDが欠落/削除済みならSnackBar案内のみ
5. 読解画面の「単語帳」長押しで使い方シート（次へ／訳を付ける／単語帳の順）が開く
6. 問題文解析・標準語彙テスト・Ⅴの発音チェックなど、他画面のダブルタップヒントと＋長押しシートが従来どおり動く
