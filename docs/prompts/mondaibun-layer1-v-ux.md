## Step 1 — データモデル：レイヤーⅠ完了条件を「語彙テスト実施」に差し替え

### 目的
レイヤーⅠの完了判定を「理解した（`understood`）」から「当該問題文の語彙テスト実施済み」に変更し、正解率を問題文に保持できるようにする。

### 背景（現状）
- `QuestionPrompt.understood` / `isLayer1Done => understood`
- 一覧フィルタ軸: 「理解実施状況」（`layer1_question_prompt_screen.dart`）
- 横断一覧のⅠ列も `isLayer1Done`（`question_prompt_overview_row.dart`）
- 総評では別途「分からなかった単語」に対する語彙力確認を実施できる

### 指示
1. `QuestionPrompt` にレイヤーⅠ語彙テスト結果のフィールドを追加する（名前は既存スタイルに合わせる）。最低限:
   - 実施済みフラグ、または正解数／出題数から導けること
   - 正解率（または正解数・出題数。表示・5点換算に使えること）
   - 出題に使った単語スナップショット（後 Step の再表示・総評用。単語・読み・訳・例文を持てること）
2. `isLayer1Done` を **語彙テスト実施済み** に変更する。
3. `understood` は:
   - **新規 UI からは書かない**（次 Step でボタン廃止）
   - JSON からは当面読み書きしてよい（後方互換）。`hasUserData` 等に残すなら、語彙テスト結果側も必ず含める
4. フィルタ・進捗・一覧ラベルを「理解実施状況」→「語彙テスト実施状況」（または同等の分かりやすい語）に更新。`QuestionPromptService` の絞り込み API も合わせる。
5. マイグレーション: 旧データで `understood==true` だが語彙テスト未実施のものは、完了扱いには**しない**（語彙テスト実績が無い＝未実施）。必要ならコメントで方針を残す。
6. 関連テスト（`question_prompt_service_test` / layer1 系）を更新。

### 受け入れ
- `isLayer1Done` が語彙テスト実施に紐づく。
- 一覧・横断一覧・フィルタの文言／判定が一貫している。
- 既存 JSON を読んでも落ちない。
- `flutter analyze` が通る。

## Step 2 — レイヤーⅠ詳細：「理解した」廃止 →「問題作成」＋ Chrome AI 単語抽出

### 目的
詳細画面の「理解」トグルをやめ、同じ枠位置に「問題作成」アイコンボタンを置き、問題文から語彙テスト用単語を Chrome AI に抽出させる。

### UI（枠位置厳守）
現行（`layer1_question_prompt_detail_screen.dart`）:
```
PrepLabelRow: [理解][ダミー][ダミー]
```
変更後:
```
PrepLabelRow: [問題作成][ダミー][ダミー]
```
- 「理解」アイコン／トグル／`understood` 更新ロジックを削除（または到達不能なら削除）
- 「問題作成」は**アイコンのみ**（推奨例: `Icons.quiz_outlined` / `Icons.auto_awesome` など既存トーンに合うもの。新規でも可だが派手にしない）
- ツールチップ／ヒント文言: 「問題作成」または「語彙テストを作成」
- 抽出済み・テスト実施済みのとき、ボタンの `active`（青塗り）などで状態が分かるとよい（既存 `conclusionActive` 相当）

### Chrome AI プロンプト（新規テンプレートファイル）
`lib/data/` に既存 `*_ai_prompt_template.dart` と同型のテンプレートを追加する。

**参考にする抽出ルール（ユーザー提供・Gemini案をベースにアプリ用へ整形）:**

あなたは日本語教育（特にJSSTやBCTなどのビジネス日本語テスト）の専門家です。  
以下の【問題文】から、学習者が文脈理解でつまずきやすい難易度の高い単語を最大5つ抽出してください。

【抽出ルール】
1. 除外対象（絶対に抽出しない）:
   - 代名詞・指示語（私、あなた、これ、そこ、どこ 等）
   - 助詞・助動詞・形式名詞・接尾辞（〜の、〜です、こと、もの、人、〜たち 等）
   - 初級・基本語彙（行く、見る、する、良い、広い、ボランティア 等）
   - オノマトペ・擬音語・擬態語（しっかり、ゆっくり、どんどん 等）
2. 抽出優先度:
   - 高: JLPT N1〜N2相当、ビジネス・社会的抽象名詞、サ変動詞、和語動詞、複合語・慣用表現
   - 低: JLPT N3以下の日常語・外来語
3. 問題文中の語彙をスコアリングし、難易度の高い上位最大5つを厳選する。
4. **どうしても5つ取れない単純な問題文では、5未満でもよい**（0件は避け、取れるだけ出す）。

【アプリ用・必須の追加出力】
不正解時にすぐ単語カード登録するため、**追加の AI 往復を不要**にする。各単語について必ず含める:
- 表記（問題文中の形）
- かな読み
- 品詞
- 難易度目安（N1/N2/N3 等）
- **意味（学習者の表示言語に合わせた短い訳。アプリ言語 ja/en/vi に応じてテンプレ側で指示）**
- **例文（その語を使った短い自然な文）**
- 例文の訳（任意だがあるとよい）

【出力】
- パース容易な **JSON** を主とする（既存の語彙 AI／発音 AI と同様）。人間向けの「■難易度上位5単語」形式は参考に留め、実装は JSON パース優先。
- スキーマ例（実装で調整可）:
```json
{
  "words": [
    {
      "word": "調整",
      "reading": "ちょうせい",
      "pos": "名詞",
      "jlpt": "N2",
      "meaning": "...",
      "example": "...",
      "exampleTranslation": "..."
    }
  ]
}
```

### フロー
1. 「問題作成」タップ → 既存の Chrome AI 送信同意／`ChromeAiSubmitMixin` パターンでプロンプト送信
2. 戻ってきたら貼り付け → JSON パース → 問題文に単語スナップショット保存
3. パース失敗時は既存と同様のエラーメッセージ

### 指示
- ヘルプ文言（`+` 長押し／`gradus_l10n` の「理解」説明）を「問題作成」向けに更新
- Step 3 で語彙テスト本体を繋ぐ前提なので、この Step では「抽出→保存→（可能なら次画面へ渡す準備）」まででよい。抽出直後にテスト画面を開いてもよいが、不正解の自動登録は Step 3

### 受け入れ
- 「理解した」ボタンが UI から消えている
- 「問題作成」が旧「理解」と同じ枠位置にある
- Chrome AI 往復で最大5語（未満可）が問題文に保存される
- `flutter analyze` ＋関連テスト更新

## Step 3 — レイヤーⅠ内で語彙テストを完結（不正解→単語カード自動登録）

### 目的
抽出した単語で語彙テストをレイヤーⅠ詳細フロー内で実施し、総評に頼らず完結させる。不正解語は自動で単語帳登録する。

### 指示
1. 抽出単語を `VocabularyEntry` 相当（または一時エントリ）に変換し、既存 `Layer1VocabScreen.fixedEntries` ＋ `questionPromptId` / `questionPromptBody` を再利用してテストする（10問固定ではなく**抽出数＝出題数**。最大5）。
2. 採点完了（全問回答＋必要なら既存どおり紙飛行機評価、または STT 照合だけで完結するならその方針を明示）後:
   - 正解率を `QuestionPrompt` に保存 → `isLayer1Done == true`
   - `SavedVocabularyCheck` にも `questionPromptId` 付きで残す（既存フィールド活用）
3. **不正解の単語**は `VocabularyService` へ自動登録:
   - 読み・訳・例文は Step 2 で AI に作らせたものを使う（再問い合わせ禁止）
   - 既に同じ表記が単語帳にある場合は二重登録しない（既存の重複判定があれば流用）
   - `QuestionPrompt.registeredWordIds` にも足す
4. テスト中／完了後の導線:
   - 詳細に戻ったとき「問題作成」が実施済み見た目になる
   - 再実施可否は既存語彙テストのやり直し方針に合わせ、最低限「未実施→実施」は必ず動く
5. 一覧進捗・フィルタが実施済みを正しく数えること

### 受け入れ
- レイヤーⅠだけで語彙テストが完了し、正解率が問題文に残る
- 不正解語が訳・例文付きで単語帳に入る（追加の AI 往復なし）
- 総評を開かなくてもレイヤーⅠ完了になる
- テストあり

## Step 6 — レイヤーⅤ詳細：「問題作成」で関連単文10個を生成し発音テスト

### 目的
レイヤーⅠと同じデザイン・同じ枠位置に「問題作成」を置き、問題文と**関連した**単文を Chrome AI に10個作らせ、それで発音テストする。

### UI
問題文詳細（Ⅴ）の `PrepLabelRow` 先頭スロット（Ⅰの「問題作成」と同じ位置・同じアイコン／見た目）に「問題作成」を配置。

### Chrome AI プロンプト（新規 or 既存テンプレ拡張）
要件（厳守）:
1. 入力は当該【問題文】（状況 Cond があればそれも含む）
2. **問題文に関連して**単文を作る（無関係な発音ドリル文だけにしない。語彙・場面・テーマを問題文から引き継ぐ）
3. 採点項目がバランスよく入る: **「つ」「ざ行」「ラ行」「長音」「促音」**
   - 目安: 各カテゴリがおおむね均等（現行ランダムの「各カテゴリ2問＝10問」に合わせるのが望ましい）
4. 出力はパース用 JSON（例: `[{ "text": "...", "category": "tsu"|"za"|"ra"|"long"|"sokuon" }, ...]` を10件）
5. 生成文は学習者が音読しやすい短文

### フロー
1. 「問題作成」→ Chrome AI → 貼り付け → 10単文を問題文に保存（フィールド追加が必要なら Step 1 と同様にモデル拡張＋マイグレーション）
2. 保存した単文で Step 5 の統一 UI 発音セッションを開始
3. 採点結果を従来どおり `pronunciationScores`（つ／ざ／ラ／長音／促音）へ反映
4. 紙飛行機→総評の導線は維持

### 受け入れ
- Ⅰと同じ位置・同系デザインの「問題作成」がある
- 生成文が問題文と関連し、5カテゴリが偏りすぎない
- その10問で発音テスト→スコア保存まで通る
- 既存の「ランダム」（グローバル短文プール）も動く

## Step 7 — ダブルタップでボタン機能ヒントを表示（基盤）

### 目的
アイコンボタンが多く、長押しが別機能に取られていると意味が分からない問題を解消する。**ダブルタップ**で「タップ／長押し」の説明を出し、他アクションまたは一定時間で消す。

### 表示例
```
タップ：問題文作成
長押し：なし
```
長押しに機能がある場合:
```
タップ：訳を付ける
長押し：自動送信で訳付け
```
（文言は各ボタンの実機能に合わせる。l10n）

### 指示
1. 共通コンポーネント（例: `ButtonActionHint` / Overlay / 既存 SnackBar ではない薄いフローティング）を用意
2. `GhostPill` / `TransportIconButton` / 必要なら `LayerNumeralBadge` 等にダブルタップ検出を足す
   - 既存の `tooltip`（長押し Tooltip）と競合しないこと
   - `onLongPress` があるボタンでも、ダブルタップヒントは出ること
3. 表示中に**他のアクション**（別ボタンタップ、スクロール開始、画面遷移、同じボタンの通常タップが実行される等）が入ったら**即座に消去**
4. この Step では表示時間の既定を仮に **3秒** でよい（設定化は Step 8）
5. まずは問題文詳細まわり（Ⅰの問題作成、訳付、単語帳、Ⅱバッジ、Ⅴの問題作成・マイク等）から適用し、パターンが固まれば他画面へ広げてよい
6. アクセシビリティ: ヒント自体は読み上げ可能なテキストに

### 受け入れ
- 対象ボタンをダブルタップすると例の形式で意味が出る
- 別操作で即消え、放置でも約3秒で消える
- 通常の単タップ／長押しの本来機能を壊さない

## Step 8 — 設定：ヒント表示期間 ＋「次のアクションまで表示」ON/OFF

### 目的
ダブルタップヒントの消え方を設定画面から変えられるようにする。

### 設定項目（`TtsSettingsScreen` にセクション追加）
1. **次のアクションが入るまでボタンの意味を表示**（Switch）
   - **OFF（既定）**: 表示期間が過ぎたら消去。既定の表示期間は **3秒**
   - **ON**: 表示は実質無限。**次のアクションが入ったら消去**（時間では消さない）
2. **表示期間**（OFF のとき有効）
   - 設定画面で変更可能（例: 秒数ピッカー、または 2/3/5/8 秒の選択）。既定 3 秒
   - ON のときはグレーアウトまたは説明文のみ

永続化: `AppSettings` / `AppPreferences`。マイグレーション不要なら既定値フォールバックで可。

### 指示
- Step 7 のヒント基盤が設定値を読むように接続
- l10n（ja/en/vi）
- 設定変更が即座に次のヒント表示に反映されること

### 受け入れ
- OFF + 3秒で自動消去
- ON で時間経過しても残るが、他アクションで消える
- 表示期間を変えると OFF 時の消え時間が変わる

## Step 9 — 総評ヘッダー：Ⅰ〜Ⅴアイコン＋点数

### 目的
総評画面上部に、アプリトップと同じレイヤーアイコン列と、各レイヤー点数を表示する。

### レイアウト
```
Ⅰ　　Ⅱ　　Ⅲ　　Ⅳ　　Ⅴ     ← 起動画面と同じ色付き丸＋ローマ数字
5　　5　　4　　5~6　　4       ← 各レイヤーの点数（未実施は「ー」）
```
Ⅳのバンド表記は**半角 `~`**（例: `5~6`）。ハイフン `5-6` にも全角 `〜` にもしない。既存 `JsstReferenceSamples.levelLabel` は全角 `〜` だが、総評ヘッダーでは半角に揃える（他画面のラベル実装まではこの Step で変えなくてよい）。

### 点数定義（確定）

| 列 | 定義 | 表示 |
|----|------|------|
| Ⅰ | レイヤーⅠ語彙テスト正解率を **5点法に換算** | `1`〜`5` または `ー` |
| Ⅱ | 的中度評点（`hitScore`） | そのまま、未実施 `ー` |
| Ⅲ | PREP評点（`prepScore`） | そのまま、未実施 `ー` |
| Ⅳ | JSST評点 | バンドを **半角 `~`** で表示（例: レベル3なら `5~6`）。ヘッダーは狭いので **`JSST ` 接頭辞は省略**。ハイフン・全角 `〜` は使わない |
| Ⅴ | 発音テストを5点法で表す。**「つ」「ざ行」「ラ行」「長音」「促音」評点の最小値** | 最小値、いずれか未記入なら方針を決めて `ー` または記入済みのみの最小（**推奨: 5カテゴリすべて揃ってから最小値、否则 `ー`**） |

#### Ⅰの5点換算（推奨・実装時に関数化）
正解率 \(r\)% を例:
- \(r = 0\) → 1（実施済みで0%のとき。未実施は `ー`）
- それ以外は四捨五入で 1〜5 にマップ（例: `score = max(1, min(5, (r / 20).round()))` など）
- 換算式は1か所にまとめ、テストで固定する。完了報告に式を書くこと

#### Ⅴ
ユーザー指定どおり **5カテゴリ評点の最小値**（すでに 1〜5 なら換算不要）。

### 指示
1. `question_prompt_summary_screen.dart` のタイトル直下（問題文抜粋の上下どちらでも、ヘッダーとして一目で分かる位置）に配置
2. アイコンは `LayerNumeralBadge` または起動画面タイルと**同じビジュアル言語**（色は `kLayerColors`）
3. Step 4 で入れた正解率テキスト表示と矛盾しないこと（本文側に詳細、ヘッダーに換算点、など役割分担を明確に）
4. ウィジェットテストで換算・最小値・JSST `5~6`（半角チルダ）表示をカバー

### 受け入れ
- 総評を開くとⅠ〜Ⅴアイコンと点数が並ぶ
- 未実施は `ー`
- Ⅳは半角 `5~6`（ハイフン・全角 `〜` にしない）
- Ⅴは5カテゴリ揃時に最小値

## Step 10 — ヘルプ整合 ＋ エキスパートレビュー

### 目的
Step 1〜9 実装後のコードベースを、ヘルプ／文言と実機能が一致している状態に揃え、エキスパートプログラマとしてレビューする。明らかで安全な修正は同セッションで直す。大きな設計変更が必要なら提案のみ。

### 先にやること：ヘルプ文と今の機能の整合

次を**実際の UI・コードと突き合わせ**て更新する（ja/en/vi すべて）。

| 場所 | パス目安 |
|------|----------|
| ヘルプ画面 | `lib/views/help/help_screen.dart` / `lib/data/layer_help_tips.dart` |
| `+` 長押しの使い方シート | 各レイヤー詳細の `LayerHelpSheet` / `gradus_l10n` の `*_使い方_*` |
| 起動サブタイトル・入口ラベル | `launch_screen` / 各 `*_entry_screen` |
| ツールチップ・空状態・フィルタラベル | 例: 旧「理解した」「10問テスト」「語彙力確認」が残っていないか |
| ダブルタップヒント文言 | Step 7 の「タップ：／長押し：」が実機能と一致しているか |

特に今回の変更でずれやすい点:
- レイヤーⅠ: 「理解した」→「問題作成」＋語彙テスト完結。完了判定は語彙テスト実施
- 総評: 語彙テスト起動なし。正解率の淡々表示＋ヘッダー点数
- レイヤーⅤ: 「10問テスト」→「ランダム」。問題文経路は関連単文10の発音セッション
- ダブルタップヒントと、長押しに別機能があるボタン

### レビュー観点（この4つに限定）

エキスパートプログラマとして、下記視点でレビューする。

1️⃣ **重複している機能（設計の狙いと異なっているもの限定）**  
   意図的な併存（例: レイヤー別一覧と横断一覧、Ghost 枠の予約席、グローバル「ランダム」と問題文由来10問）は指摘しない。  
   **設計の狙いから外れた二系統**（同じことを別実装・別保存・別導線でやっており、仕様上一本のはず）だけを挙げる。安全なら共通化／片方削除する。

2️⃣ **ゾンビ化している機能**  
   到達不能な画面、押しても何も起きないボタン、使われない l10n キー、死んだ prefs キー、旧「理解した」「語彙力確認」「10問テスト」表記、参照ゼロのテンプレ／メソッド。

3️⃣ **動線が冗長的な機能**  
   同じ目的に余分な画面・確認・AI 往復が増えている箇所。スキップ遷移の欠落。総評を経由しないとⅠが完了できない、などが残っていないか。

4️⃣ **その他**  
   ヘルプ文に限らない。文言と機能の不整合、ローカライズ漏れ（ja だけ更新、en/vi 未訳、キー欠落）、表示と実装の食い違い（点数の `~` / `ー`、ヒントの ON/OFF など）、アクセシビリティの明らかな欠落。

### 成果物
- レビュー結果を `docs/prompts/mondaibun-layer1-v-ux-review.md` に短くまとめる（観点①〜④。各項目は **修正済 / 意図的残置 / 提案のみ** を明示）。
- 明らかで安全な修正（ヘルプ・文言・ゾンビ削除・ローカライズ穴）は同セッションで直す。
- `flutter analyze` が通ること。関連テストが赤なら直す。

### 受け入れ
- ヘルプ／使い方シート／入口文言が Step 1〜9 後の UI と矛盾していない。
- レビュー文書がある。
- 致命的な（設計意図と異なる）重複・ゾンビ・冗長動線・文言不整合が残っていない。残すものは文書で意図的残置理由がある。

## 推奨実装順と依存

```
Step 1  データ（Ⅰ完了＝語彙テスト）
  → Step 2  Ⅰ「問題作成」＋単語抽出 AI
    → Step 3  Ⅰ内語彙テスト＋不正解自動登録
      → Step 4  総評から語彙テスト撤去・正解率表示
Step 5  Ⅴ入口「ランダム」＋発音 UI 統一
  → Step 6  Ⅴ「問題作成」＋関連単文10・発音テスト
Step 7  ダブルタップヒント基盤
  → Step 8  設定（表示期間 / 次アクションまで）
Step 9  総評ヘッダー（Step 1・3・4・6 のスコアが揃っていると確認しやすい）
  → Step 10 ヘルプ整合＋レビュー（①重複※設計意図と異なるもの ②ゾンビ ③冗長動線 ④文言・l10n 他）
```

Step 5–6 と Step 1–4 はデータ衝突が少なければ並行可能だが、**1セッション1 Step** を推奨。  
Step 7–8 は他 Step と並行しやすい。  
Step 9 は Step 1・3・4 完了後が望ましい（Ⅴ点数は Step 6 後に本確認）。  
Step 10 は **Step 1〜9 完了後**に単独セッションで行う。
