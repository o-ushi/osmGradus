# 問題文（旧・お題）取り扱い大幅改修 — Claude Code 用ステップ別プロンプト

このファイルは Claude Code 向けの実装指示書です。  
ユーザーは次のように指示します。

> `docs/prompts/mondaibun-rebuild.md` の Step N をやって

各 Step は**独立して実行できる粒度**に分けています。前 Step が完了している前提で書いてあります。  
1 Step = 1 セッション推奨。終わったら `flutter analyze`（または該当テスト）で破綻がないことを確認してから次へ進んでください。

---

## 共通ルール（全 Step 共通・必ず守る）

1. **既存のボタン枠位置を動かさない**  
   詳細画面のコントロールは、既存の  
   `DiceActionRow`（45 / 60 / 15+60 / ＋）、分野セレクト、本文カード、サイコロ／スピーカー、  
   `PrepLabelRow` / `PrepStageRow`（結論・理由・例）、再生 / リセット / 紙飛行機  
   の**予約席レイアウト**を維持する。非表示は `GhostPill` / `visible:false` で枠だけ残し、位置がズレないようにする（既存コメントの方針どおり）。
2. **アイコン優先** — 新規ボタンは極力アイコンのみ（ツールチップで名称）。
3. **レイヤーローマ数字の見た目** — トップ画面 `LayerListTile` / `AppHeader` と同じ  
   色付き丸＋Unicode `Ⅰ`〜`Ⅴ`（`kLayerColors`）。遷移ボタン「II」「III」「IV」「V」も同じデザイン言語に合わせる。
4. **l10n** — ユーザー向け文言は `gradus_l10n.dart` / `app_strings.dart` 経由。ja/en/vi を揃える。
5. **永続化** — 現状どおり SharedPreferences（Hive/SQLite は新規導入しない）。マイグレーションを必ず書く。
6. **スコープ外を触らない** — その Step の受け入れ条件以外のリファクタ・ドキュメント追加はしない。
7. **完了報告** — Step 終了時に「変更ファイル一覧」「手動確認手順」「次 Step への前提」を短く報告する。

## Step 0 — アプリ内「お題」→「問題文」置換

### 目的
ユーザー向けの「お題」表記を「問題文」に名称変更する。

### 指示
1. `lib/` 配下でユーザーに見える「お題」を「問題文」に置換する（l10n キーの**値**、画面文言、ヘルプ、ツールチップ、プレースホルダ）。
2. 英語・ベトナム語も意味が通るように更新する（例: topic / prompt → question / problem statement など、文脈に合う語を選ぶ。機械的に全部 `topic` のまま残さない）。
3. **コード識別子**（クラス名 `TopicService`、ファイル名 `topic_*.dart`、prefs キー `topics.*`）は**この Step では変更しない**。コメント内の「お題」はユーザー向け説明なら「問題文」に、技術コメントは任意。
4. バックアップ説明・プライバシー文言・`docs/` のユーザー向け記述で「お題」が残っていれば同様に直す（実装手順書 `docs/prompts/*` は触らない）。

### 受け入れ
- アプリ UI / ヘルプを日本語で見たとき「お題」が実質残っていない（開発者向け内部名は除く）。
- `flutter analyze` が通る。

## Step 1 — 問題文データベースの拡張

### 目的
問題文を「文字列のリスト」から、下表の項目を持つ永続エンティティに拡張する。

### スキーマ（確定）

| 項目名 | 内容 | 備考 |
|--------|------|------|
| id | 一意 ID | 新規。既存データ移行時に付与 |
| source（入手元） | 組込み / AI / 手入力 / インポート | enum |
| field（分野） | 日常の身近な話題 / ビジネスシーン / シチュエーション | 既存 `TopicCategory` の daily/business/situational に対応。`random` は分野としては持たない |
| body（本文） | 問題文本文 | シチュエーションは状況＋条件を本文側でどう持つか設計し、既存表示と互換を維持 |
| understood（理解） | yes / no | 既定 no |
| registeredWords（登録単語） | ユーザー登録単語 | 単語 ID またはテキスト＋メタ。長文の `VocabularyService` と重複実装しないよう設計 |
| summary（要約） | 回答の要約 | 文字列、空可 |
| conclusion（結論） | 回答の結論部 | |
| reason（理由） | 回答の理由部 | |
| example（具体例） | 回答の例示部 | |
| jsstScore | JSST スコア | 未実施は null |
| hitScore（的中度） | 的中度スコア | 未実施は null |
| prepScore | PREP スコア | 未実施は null |
| pronunciationScores | 「つ」「ざ・ず・ぞ」「ラ行」「長音」「促音」 | 各 null 可 |
| advice | Chrome AI からのアドバイス | 文字列、空可 |

### 指示
1. モデル（例: `QuestionPrompt` / `Mondaibun` など分かりやすい名前）と JSON シリアライズを追加。
2. `TopicService` を拡張するか、後継サービスに置き換え、CRUD・フィルタ・進捗集計 API を用意する。
3. **マイグレーション**
   - 組み込み `TopicBank` → source=`組込み`
   - 既存 imported prefs → source=`インポート`（または当時の入手経路が分かるならそれに合わせる）
   - 旧データに無い項目は既定値（understood=no、スコア null、テキスト空）
4. 既存の抽選 `drawRandom`・取り込み UI（AI / 手入力 / JSON）が壊れないよう、取り込み時に `source` を正しく立てる。
5. レイヤーⅣの `ScoringResultStorage`・レイヤーⅤの `PronunciationCheckStorage` との突合は、この Step では**無理に統合しなくてよい**が、後 Step で問題文 ID に紐付けられるよう ID 設計だけ意識する（コメントで方針を残す）。

### 受け入れ
- 既存インストール相当のデータを読み直しても落ちない。
- 組み込み＋取り込み問題文が一覧取得できる。
- 各フィールドの読み書き単体テスト、または小さなサービステストがある。

## Step 2 — レイヤーⅠ：入口＋問題文一覧＋詳細（解析）

### 目的
レイヤーⅠトップと「問題文解析」フローを仕様どおりにする。

### トップ画面レイアウト
```
[語彙を増やす]
  アイコン＋「問題文解析」  ← 新規アイコン
  アイコン＋「長文読解」    ← 既存アイコンで OK
  アイコン＋「単語テスト」  ← 既存アイコンで OK
[日本語に耳を慣らす]
  アイコン                 ← 既存で OK
```
`layer1_entry_screen.dart` の `_Layer1ModeSelect` を拡張する。

### 問題文一覧（レイヤーⅠ）
- 上部: **進捗度**（理解=yes の件数 / 総数 × 100%）＋**フィルタアイコン**
- フィルタ: 入手元 / 分野 / 理解実施状況
- 行（1行・本文は `…` 省略）:

| 理解 | 本文 |
|------|------|
| ☑️ / 🔲 | 本文… |

- 行タップ → 詳細

### 詳細画面（レイヤーⅠ）— 枠配置（位置厳守）
```
[ダミー][ダミー][ダミー][+]
[ダミー] ← 分野リストは非表示（枠のみ）でも、既存と同じ位置に枠を残す
本文
[ダミー] ← サイコロ相当は非表示
[理解][ダミー][ダミー]
[訳付][単語帳][II]
```
- `+` : 長押しで操作方法（既存 `LayerHelpSheet` 方針）
- `理解` : 旧「結論」枠位置。yes/no トグル。yes で背景青、no で透明
- `訳付` : 長文読解と同じ挙動
- `単語帳` : 単語帳表示
- `II` : レイヤーⅡ詳細へ（問題文は変えない）。見た目は起動画面のレイヤーⅡタイルに合わせる
- その他ダミー: 隠す（枠は維持）

### 単語登録
- 本文を長押し＋ドラッグで選択 → 単語帳登録
- **長文読解の `TappableJapaneseText` 等を流用**し、重複実装しない

### 受け入れ
- 入口に「問題文解析」が増え、一覧→詳細→理解トグル→単語登録→Ⅱ遷移ができる。
- 長文読解・単語テスト・Podcast の既存動線が壊れていない。

## Step 3 — レイヤーⅡ：入口＋一覧＋詳細（要約）

### 目的
レイヤーⅡを「回答をイメージする／話題を増やす」入口と、問題文ベースの要約フローにする。

### トップ
```
[回答をイメージする]  ← 新規アイコン → 問題文一覧
[話題を増やす]        ← 🌐 → 既存の話題追加／検索に相当する動線（現行 Layer2 の🌐や＋取り込みと整合）
```

### 一覧（Ⅱ）
- 進捗 = **要約が記入された件数** / 総数 × 100%
- フィルタ: 入手元 / 分野 / 要約記入状況
- 的確度（的中度）列: レイヤーⅣ実施済ならそのスコア、未実施は「ー」

| 要約（省略） | 的中度 | 本文（省略） |
|--------------|--------|--------------|
| … | 5 or ー | … |

### 詳細（Ⅱ）
```
[ダミー][ダミー][ダミー][+]
[ダミー] ← 分野
本文
[ダミー] ← サイコロ
[要約][ダミー][ダミー]
[ダミー][ダミー][III]
```
- `要約`: タップでテキスト入力。既存値を表示。記入済なら背景青
- `III`: レイヤーⅢ詳細へ（問題文固定）。デザインは起動画面Ⅲに合わせる
- **Ⅰの「II」から来た場合**: トップ・一覧をスキップし、同じ問題文のⅡ詳細を直接開く

### 受け入れ
- サイコロ中心だったⅡの主経路が「一覧→要約」になる（ランダム抽選はⅢ以降の「ランダム」や既存に残してよいが、Ⅱトップ仕様は上記優先）。
- Ⅰ→Ⅱのスキップ遷移が動く。

### 目的
Ⅲを「一覧から選ぶ／ランダム」＋ PREP（結論・理由・具体例）記入にする。

### トップ
```
[問題文一覧から選ぶ]  ← 新規アイコン → 一覧
[ランダム]            ← 新規アイコン → 現行のサイコロで問題文を選ぶ画面
```

### 一覧（Ⅲ）
- 進捗 = 結論・理由・具体例が**全て**記入された件数 / 総数 × 100%
- フィルタ: 入手元 / 分野 / PREP 記入状況
- PREP スコア列: Ⅳ実施済ならその値、未実施「ー」

| PREP | PREPスコア | 本文 |
|------|------------|------|
| 済 / （未） | 5 or ー | … |

### 詳細（Ⅲ）
```
[ダミー][ダミー][ダミー][+]
[ダミー] ← 分野
本文
[ダミー] ← サイコロ（ランダム経路で選んだ直後など、必要なら表示方針を既存と整合。一覧経由では隠して枠維持で可）
[結論][理由][具体例]
[ダミー][ダミー][IV]
```

- `IV`: Ⅳ詳細へ（問題文固定）。デザインは起動画面Ⅳ
- **Ⅱの「III」から来た場合**: トップ・一覧スキップでⅢ詳細直開

### 受け入れ
- PREP 3項目の保存と一覧の「済」判定が一致する。
- ランダムは既存サイコロ体験を再利用できる。

| JSST評点 | 本文 |
|----------|------|
| 5~6 / ー | … |

```
[45][60][15+60][+]
[ダミー] ← 分野
本文
[スタート] ← サイコロ枠の位置をスタートに転用（既存 PracticeLayer の開始導線に合わせる）
```

## Step 8 — ダッシュボードへの反映

### 目的
問題文フローで得た結果を、起動ダッシュボードの評価集計に含める。

### 指示
1. `DashboardSummaryService` が参照する入力に、問題文エンティティ上の JSST / 的中度 / PREP / 発音（および必要なら語彙理解）を加える。
2. 既存の `ScoringResultStorage` / `PronunciationCheckStorage` / `VocabularyCheckStorage` と**二重計上しない**よう、ソースオブトゥルースを決めて統合または変換する。
3. ダッシュボード AI プロンプトテンプレートも、新しいデータが説明に載るよう更新。
4. 「どの結果が集計に入るか」をヘルプ or 画面上の短い説明で矛盾なくする（本格ヘルプ整合は Step 10）。

### 受け入れ
- 問題文詳細で保存したスコアがダッシュボード指標に反映される。
- 同じ練習を二重に平均しない。

## Step 10 — 総仕上げレビュー（神のプログラマ視点）

### 目的
実装後コードベースをレビューし、必要なら最小限の修正まで行う。

### レビュー観点
1. **重複機能** — 同じ単語選択・同じ取り込み・同じ一覧が二系統になっていないか。共通化できるなら共通化。
2. **ゾンビ機能** — 到達不能な旧サイコロ専用画面、使われない l10n キー、死んだ prefs キー、ダミーのまま残った導線。
3. **冗長な動線** — 同じ問題文に行くのに余分な画面が多い箇所。スキップ遷移の欠落。
4. **ヘルプ整合** — `layer_help_tips.dart` / `+` 長押しヘルプ / `help_screen` / 起動サブタイトルが新 UI と一致しているか。
5. **その他** — アクセシビリティ（tooltip）、マイグレーション安全性、パフォーマンス（全件ロード）、analyz 警告。

### 成果物
- レビュー結果を `docs/prompts/mondaibun-rebuild-review.md` に短くまとめる（観点①〜⑤）。
- 明らかで安全な修正は同セッションで直す。大きな設計変更が必要なら提案のみ。

### 受け入れ
- レビュー文書がある。
- 致命的な重複・ゾンビ・ヘルプ矛盾が残っていない（または文書で意図的残置理由がある）。
