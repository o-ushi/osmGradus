## ① 重複している機能

| 判定 | 内容 |
|------|------|
| **意図的残置** | 25マス一覧のシステムセットタイルは`ThinkingMatrixExpansionService.cellWeight`を直接再利用した拡充度%（Step 5）、盤面ヘッダーは従来の`completionRatio`（キーワード埋まり率、`n/25`表示）。同じセットで2つの%が別意味で出るが、ラベルが「達成率」と「拡充度」で明確に分かれており、ロジックの二重実装ではない（片方が片方を呼ぶ／独自再計算する、という重複はない）。盤面ヘッダーを拡充度%に統一しない判断はStep 5の指示どおり（トロフィー・セル色と同じく盤面練習UXは変更しない）。 |
| **確認** | 「総合」の旧意味（5指標平均）を指す文言は、画面・トランスクリプト・AIプロンプト・ヘルプいずれにも残っていない。`help.gradus.dashboard.tip2`はStep 6で「テスト総合は…」に書き換え済み、`overallGradeDisplay`は文字のみ（`overallGrade.letter`）で「総合」行にのみ使われる。 |
| **確認** | ユーザー追加の同カテゴリセット（「追加の日常セット」等）は`ThinkingMatrixService.systemSetIds`のID一致でのみ拡充度計算に入るため、誤混入しない。`thinking_matrix_expansion_service_test.dart`・`dashboard_summary_service_test.dart`双方に混入防止テストあり。 |

致命的な「同じ値を2箇所で別計算していて食い違う」二重実装は無い。

## ③ 動線が冗長的な機能

| 判定 | 内容 |
|------|------|
| **確認** | `ThinkingMatrixService.ensureSystemPresets()`はダッシュボード`initState`と各履歴画面から戻った直後、およびトランスクリプト`initState`でのみ呼ばれる（画面を開くたびに際限なく増殖する経路は無い）。中身は`loadAll`＋不足カテゴリだけ`save`なので、複数回呼んでも2回目以降は書き込みが発生しない（Step 1・7のテストで冪等性を確認済み）。 |
| **該当なし** | システムセット作成のための専用画面遷移は無い。ダッシュボード／トランスクリプト／25マス一覧のいずれも、既存の画面を開くだけで裏側にシードされる。 |
