# 使い方画面 実装レビュー（Step 6）

`docs/prompts/usage-screen.md` の Step 1〜5 実施後のコードを、①重複 ②ゾンビ ③冗長な動線 ④ヘルプ／設定ラベルと実装の不一致 ⑤＋長押し・ダブルタップ案内の食い違い、の観点で点検した結果。

## ① 重複

- **使い方画面の本文とヘルプ「操作の基本」tip4**（Chromeコピーボタンの案内）は同じ内容を2箇所で説明している。→ **意図的残置**。使い方画面は初回・スワイプ時のワンショット案内、ヘルプはいつでも参照できる恒久リファレンス。ユーザーが読み飛ばした／忘れた場合の再確認先として意図的に重複させている。
- **ホーム下部の`起動_操作ヒント`と使い方本文の「＋長押し」説明**は同じ操作を指している。→ **意図的残置**（仕様書にも明記済み）。使い方をスキップした人・日常のリマインド用。
- **設定画面のスタートアップ／使い方スイッチの構成**（`SettingsSwitchRow`×2）はコピペに近い形だが、2画面分のみで共通ウィジェット化するほどの重複ではない。→ **確認**（仕様書のコメント通り、共通化は必須ではない）。

## ② ゾンビ

- `StartupScreen`から`起動_操作ヒント`のTextとその`SizedBox`を削除済み。l10nキー自体はホーム（`LaunchScreen`）が引き続き参照するため未削除。→ **修正済み**（削除漏れなし、キー削除もしていない）。
- `LaunchScreen.onShowStartup`は「必ずスタートアップを出す」という意味のコールバック名だったが、着地先がスワイプ時点の使い方フラグで分岐するようになったため`onSwipeFromHome`へリネームし、ドキュメントコメントも新しい分岐に合わせて修正した。→ **修正済み**。
- `AppRootShell`のクラス doc コメントが`StartupScreen`・`LaunchScreen`・`MainShell`のみを列挙しており、`UsageScreen`が抜けていた。→ **修正済み**（`UsageScreen`を追記）。
- `test/startup_screen_test.dart`の旧テスト名「スタートアップ画面表示ONのとき…スタートアップ画面に戻る」は、使い方が既定ONの現行仕様では実際には使い方画面に着地するため実態と不一致だった。→ **修正済み**（テスト名を「使い方画面に戻る（仕様D）」に変更し、使い方OFF用のケースを別テストとして追加）。
- 古い「はじめる→すぐホーム」を前提にしていた既存テスト（次回表示しない系・国旗系に隣接する2本）を、使い方画面を経由する現行仕様に合わせて更新した。→ **修正済み**。

## ③ 冗長な動線

- 起動直後（コールドスタート）に使い方だけを表示する経路は作っていない（`_showingUsage`の初期値は常に`false`）。→ **確認**（仕様どおり。`showStartupScreen`がOFFなら`showUsageScreen`の値に関わらずホーム直通）。
- スタートアップとの二重ダイアログ化はない。`AppRootShell.build`は`_showingStartup` → `_showingUsage` → `LaunchScreen`の優先順位で排他的に1画面だけ表示する。→ **確認**。
- ホームからの右スワイプとボタン操作（「ホーム画面へ」）で着地矛盾がないか確認。スワイプは現在値の`showUsageScreen`を見て使い方／スタートアップへ、ボタンは各画面の`onContinue`経由で明示的にホームへ。矛盾なし。→ **確認**。

## ④ ヘルプ／設定ラベルと実装の不一致

- 設定画面のセクション見出しを「スタートアップ画面」から「案内」にリネームし、スタートアップ・使い方の2スイッチを同じカードにまとめた（仕様書の推奨どおり）。→ **修正済み**。
- ヘルプ「設定」セクションのtip2に、スタートアップ／使い方画面の表示可否を変更できる旨を追記（ja/en/vi）。→ **修正済み**。
